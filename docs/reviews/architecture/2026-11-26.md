## Comparison

| Concept | Disposition | Level | Why | Why not | Evidence |
|---|---|---|---|---|---|
| Framework-free domain core shared by the app, tools and the MCP server | adopt (keep) | project | One implementation of validation and health logic; testable without Angular; enforced by `conventions.pureDirs` | — | [fpv-core](../../architecture/fpv-core.md); outside MCP guidance warns against thin API wrappers, which a shared core avoids |
| Inference in a dedicated web worker | adopt (keep) | project | Keeps the UI thread free; outside in-browser engines all run off the main thread | — | [WebLLM paper](https://arxiv.org/abs/2412.15803v1); [Intel: in-browser LLMs](https://www.intel.com/content/www/us/en/developer/articles/technical/web-developers-guide-to-in-browser-llms.html) |
| Swap the inference runtime for another in-browser engine (WebLLM, Transformers.js) | watch | project | Outside engines differ in model coverage and memory; one research comparison reports large memory and speed gaps between them | Figures come from one party's own benchmark; switching costs a worker rewrite and model re-validation.
